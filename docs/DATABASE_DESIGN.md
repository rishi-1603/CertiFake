# Database design

`users` contains UUID-like string IDs, unique indexed email and bcrypt hashes. `analyses` has an ID, indexed owner FK (nullable for legacy data), file metadata, state (`pending`, `analyzing`, `completed`, `failed`), OCR fields, signals, legacy score/confidence columns and timestamps. API retrieval requires the requesting owner. `outbox_events` holds ID, analysis FK, topic, JSON payload, created/sent timestamps, indexes on analysis and sent status, and a unique `(analysis_id, topic)` constraint. The old score/confidence columns remain for schema compatibility but are not exposed as estimates.

Analysis/outbox transitions commit atomically; image objects do not. OCR and forensics lock the analysis row during processing, a simplicity/throughput trade-off. Pending outbox rows are separately locked for publishing. Schema is created via SQLAlchemy `create_all` with a Postgres advisory lock; **there are no schema migrations**. `create_all` does not alter old tables. Back up before upgrading and plan an explicit migration framework before schema changes to existing tables. Foreign-key and transaction behavior were exercised against the native Postgres instance by end-to-end runs; concurrent replicas, upgrade rollback and durable cleanup remain unverified.
